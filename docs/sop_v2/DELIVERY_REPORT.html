01 — 结论摘要

初跑的致命阻断已被彻底解决

另一台机器的初跑证明：项目在 Instagram 私有 API 认证阶段整体阻断——22 个账号无一能恢复为可用会话，全链路停在采集之前，产不出任何交付。同时旧漏斗把"无 Amazon 橱窗"当硬淘汰，与客户"有/无橱窗均可、未知进 Review"的双轨要求冲突。

本次交付换了地基：放弃私有 API，改用登录态 Chrome 浏览器会话采集。客户提供的账号自带有效会话 Cookie，注入浏览器即为登录态——5 个账号 5 个全部在线，全程零密码/TOTP 登录、零封号风险。初跑 22/22 的死因不复存在。在此之上，把客户 SOP 的全部判定逻辑代码化并跑通了真实数据。

06 — Storefront 穿透

聚合页 → Amazon 橱窗，已做

专门核实：Amazon 与 LTK/Linktree 等聚合页穿透已实现。逻辑分三层——bio 里 Amazon 直链直接 confirmed_yes；聚合页（Linktree / Beacons / LTK / ShopMy / Stan）用真浏览器渲染后读全部真实出链，命中 amazon.com/shop 则确认橱窗并留链接与截图；打开成功但无 Amazon 出链记 confirmed_no；LTK 联盟跳转无法自动确认的记 unknown 进 Review 待人工点查。

实测

@annascountryhome 的 linktr.ee/ourgreenwood：浏览器读取 55 个出链、无任何 Amazon 链接 → 判定 confirmed_no，并存证。"未知"被真实解析掉，而非拍脑袋。
